1 · Public catalogue and info point (no login)

1

Search by title

Open /catalog and search Sapiens, 1984, clean code (full-text also matches authors and tags).

2

Look up an ISBN that is in the catalogue

Go to /lookup and enter 9780062316110 (Sapiens) or 9780553418026 (The Martian). You should see availability counts, loan type and the aggregate “loans / year”.

3

Look up an ISBN that is not in the catalogue

Enter an ISBN we do not hold, e.g. 9780307887443 is held — use something like 9781501139154. The page should fetch public catalogues (Open Library) and show the title framed as external, with a Suggest acquisition button. Press it — later the admin sees it under Demand.

4

QR copy page

Open /i/<copy-code>. Copy codes are random per environment; get one with the SQL in the appendix. The page must show status + location and never any borrower identity, loan dates, internal notes or cost.

2 · Front desk (librarian)

1

Sign in

Log in with librarian@betsefer.local / DemoPassword-2026. The home shows role-based entries; open Front desk.

2

Check out

Reader = a member code (reader reader@betsefer.local shows its code in /account; appendix can list more) and Copy = an available code from the appendix. Leave hours empty. Expect the green “Checked out — due …”.

3

Check in

Same copy code in the Check in box → copy moves to reception. If you have an overdue reader handy, the loan cap and overdue checks return specific messages — try twice to see the friendly refusals.

3 · Shelving (shelver)

1

Queue

Log out and sign in as shelver@betsefer.local → open Shelving queue. The copy you just checked in should be at the top.

2

Advance it

Press Pick up (at_reception → in_transit) and then Shelve (in_transit → available). The card leaves the queue.

4 · Identity verification (librarian / admin)

1

Readers list

As librarian open Readers. Search works by name / email / member code. A reader account that is still pending_identity shows a quick verify form.

2

Verify + restore

Pick document type and an ID number → Verify → status becomes active. Admin-only: close an account (future) and Reopen it; reopen resets to pending_identity.

5 · Reader area (reader)

1

Dashboard

Sign in as reader@betsefer.local → My account: current loans with due/overdue, member code, status.

2

History and member card

Open History (returned loans) and Card (QR renders the member code). A reader never sees the /staff area.

6 · Acquisition suggestions (administrator)

1

Demand

Sign in as admin@betsefer.local → Demand & suggestions. The suggestion you created in section 1 appears with its book title/author snapshot, ISBN and date. Use Mark as handled and watch the badge change.

7 · Language

1

EN / ES

On the home page the top-right selector toggles the whole UI between English and Spanish (persisted per account).

Appendix — getting real codes

Copy codes and member codes are random per seed; ISBNs and titles are fixed. On the production host:

cd ~/dev/bet-sefer/backend
# 4 available copies (for check-out)
docker compose -f docker-compose.prod.yml exec -T postgres psql -U betsefer -d betsefer -c \
  "select c.code, e.title from copies c join editions e on e.id=c.edition_id where c.status='available' order by random() limit 4;"
# member codes of readers (for check-out / verify)
docker compose -f docker-compose.prod.yml exec -T postgres psql -U betsefer -d betsefer -c \
  "select u.member_code, u.name from users u join model_has_roles m on m.model_id=u.id join roles r on r.id=m.role_id where r.name='reader';"

Security notes for the reviewer: the public surface only ever exposes aggregates and an allow-list of fields — no borrower names, emails, member codes, individual loan dates, internal notes or costs are sent to anonymous visitors.
